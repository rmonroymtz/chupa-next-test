# Phase 3 report: search on Next.js

Phase 3 makes the Next.js storefront serve **the search page (`/search.html`) and the SKU search shortcut (`/{store}-{sku}-search.html`)** from the CHAPI search API, with legacy parity for query, store, sort, filters, pagination and the ChupaChoice multi-store view. It also adds an analytics module with Google Tag Manager and the recommendation sliders under the results. It is ready to deploy; go-live is the edge change in [`docs/routing/phase-3.md`](routing/phase-3.md) (deleting the temporary phase 2 search rules) and the pending items below.

How each url resolves:

| Url                                        | Shopper                                                                         | Bot                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------- | ----------------------------------- |
| `/search.html?query=q&store={chapi store}` | 200, results (or empty / error state), `noindex, follow`, sliders below         | 200, no results, no CHAPI           |
| `/search.html?query=q` (`store` missing)   | 200, ChupaChoice: amazon 12, ebay 6, target 6, acme 6                           | 200, no results, no CHAPI           |
| `/search.html?…&store=walmart` (not CHAPI) | 307 → same search with `store=chupachoice`, `storeParams` dropped               | same                                |
| `/search.html` (blank query)               | 200, prompt to type a query, no CHAPI                                           | same                                |
| CHAPI failure or timeout                   | 200, error message and "Reintentar", `noindex` (never 5xx)                      | —                                   |
| `/{vendor}-{sku}-search.html`              | 200, CHAPI product, `noindex, follow`, canonical = product url (self on a miss) | 404 `noindex`, no Magento, no CHAPI |

## Key decisions

Numbers refer to the decisions in `odd/tasks/phase-3-search.md`.

| #   | Decision                                                                                    | Legacy parity                                                                                                              |
| --- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1   | Full parity: query, store, sort, filters, pagination, ChupaChoice view                      | Same features; store switching lives only in the header search bar, as in the legacy page.                                 |
| 2   | Legacy url model `?query&store&page&storeParams`; `storeParams` is the opaque CHAPI link    | Same urls, so existing links keep working; `page` is display only, as in the legacy.                                       |
| 3   | ChupaChoice multi-store view in scope                                                       | Same lists and sizes, legacy look.                                                                                         |
| 4   | Default store `chupachoice`                                                                 | **Differs**: the legacy page defaulted to `amazon`; the header's default tab was already ChupaChoice.                      |
| 5   | Bots: 200 page without results, no CHAPI call                                               | **Differs**: legacy bots went through prerender. Same rule as phase 1 (bots never trigger CHAPI).                          |
| 6   | `noindex, follow` on every search page; robots.txt and the `SearchAction` JSON-LD unchanged | **Differs**: the legacy page had no robots meta.                                                                           |
| 7   | `*-search.html` rendered from CHAPI on the same url, canonical to the product, `noindex`    | Legacy also ignored Magento there and asked CHAPI; one request, no redirect.                                               |
| 8   | Non-CHAPI stores → 307 `chupachoice`; no Magento `searchTerm` redirect                      | **Differs** for stores (legacy fell back to Magento search); `searchTerm` matches the legacy, which dropped it (CHUP-569). |
| 9   | Extras in: fallback-store notice, GTM events, sliders. Out: header autocomplete             | Notice copy from the legacy `BackupStoreMessage`.                                                                          |
| 10  | `CHAPI_SEARCH_TIMEOUT_MS` (8 s); failure → 200 error page with "Reintentar" and a metric    | Legacy never answered 5xx either (client retries, no timeout).                                                             |
| 11  | Search card slug stays the legacy one; the Magento url key gap is a follow-up               | Same slug as the legacy (`convertChapiToMagento`).                                                                         |
| 12  | Analytics module mirroring the legacy eventing pattern; GTM only with `GTM_ID`              | Same `search` / `view_item_list` payload names; one push mechanism instead of the legacy two.                              |

Also decided during the tasks: sort options are requested after the search, only when the response has no `data.sorts` (always today on staging); pagination, sort and filter links use **the store that answered** when CHAPI serves a fallback store (the legacy kept the requested store).

## Differences from the legacy PWA

| Area                    | Legacy PWA                                                       | Next                                                                                                                                                                          |
| ----------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rendering               | Client-side SPA, SWR (3 retries)                                 | Server-rendered per request, plain links (every search navigation is a full page load), 8 s timeout and an error page.                                                        |
| Title and robots        | "{store}'s Search Result for term {q}", no robots                | `Búsqueda: {q}`, `noindex, follow`, no canonical.                                                                                                                             |
| `search` event          | Sent on the first search or a store change (in-app state)        | Sent unless the referrer is the same search (same query and store, or any `storeParams` link). A reload of a filtered page is not reported; a stripped referrer over-reports. |
| `view_item_list`        | `price: NaN`, empty `item_brand`                                 | Real price; brand when CHAPI sends one (`''` otherwise).                                                                                                                      |
| Recommendation sliders  | Legacy slider component                                          | Server-rendered carousel (`ProductCards`, CSS scroll-snap, no client JS), legacy titles, each slider streamed in its own Suspense boundary.                                   |
| Fallback store          | Links kept the requested store                                   | Links use the store that answered; when that is not a search store, products only.                                                                                            |
| Result count            | `totalProducts`                                                  | "{n} productos en esta página" (CHAPI's `totalProducts` means the page on amazon and the whole search on eBay).                                                               |
| Header search bar       | Autocomplete, last store remembered, SKU jump to `*-search.html` | None of the three: always submits to `/search.html`. `*-search.html` urls from PWA pages and old links still work.                                                            |
| ChupaChoice error box   | Message only                                                     | Message plus "Reintentar".                                                                                                                                                    |
| Search card links (SEO) | Legacy slug; PDP read only store and sku                         | Same slug and CHAPI render, plus `noindex` and a canonical (decision 11).                                                                                                     |

## Known limitations and follow-ups

| Item                                                        | Notes                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Non-vendor `/{x}-….html` urls rendered Magento placeholders | Fixed 2026-10-16: `/walmart-123456-search.html` and `/walmart-123456-foo.html` answered 200 "External URL Placeholder" `index, follow`; the placeholder check now covers every url (404 `noindex` outside `PRODUCT_VENDORS`, no CHAPI).                                                                                                                                                                              |
| Custom Magento url rewrites to products                     | A product served at a request path whose last segment is not its own `url_key + url_suffix` and does not carry its sku (a custom no-redirect rewrite) is now treated as a placeholder (404 outside `PRODUCT_VENDORS`). Same as the legacy PWA, which looks such urls up by url key. Category-prefixed product urls are kept (last segment). List Magento's custom product rewrites before go-live (see phase 2 doc). |
| SEO slug gap (decision 11)                                  | Search cards and the sku jump canonical use the legacy slug (non-ASCII → `-`); Magento url keys drop non-ASCII. For a product Magento already has, the link reaches a `noindex` CHAPI page instead of the indexable Magento page.                                                                                                                                                                                    |
| acme base64url SKU with `-`                                 | An acme SKU whose base64url contains `-` (`~~~` → `fn5-`) is read back as another SKU. Inherited from the legacy and phase 1. Count affected Magento SKUs before any format change.                                                                                                                                                                                                                                  |
| Search item slug keeps a trailing `-`                       | Titles ending in a non-ASCII character or symbol; legacy behavior.                                                                                                                                                                                                                                                                                                                                                   |
| Canonical with a literal `%` for missing products           | Phase 1 behavior, not changed here.                                                                                                                                                                                                                                                                                                                                                                                  |
| `buildSearchItemUrlKey` lives in `search/domain`            | The product module imports it for the sku jump canonical; move it to the product domain.                                                                                                                                                                                                                                                                                                                             |
| Header `useSearchParams` without Suspense                   | Works because every route is dynamic; a statically rendered route would need a Suspense boundary around it (build error or client-side rendering).                                                                                                                                                                                                                                                                   |
| Header integration assertions                               | Depend on the HTML attribute order.                                                                                                                                                                                                                                                                                                                                                                                  |
| Pagination prev link                                        | Its `page` label is `max(1, current - 1)`: when CHAPI sends a prev link on page 1 (e.g. a wrong `page` in the url), the label is clamped to 1 instead of following the link.                                                                                                                                                                                                                                         |
| Analytics dispatcher isolation (T6a review)                 | A provider's rejection is isolated only for native Promises; thenables are not.                                                                                                                                                                                                                                                                                                                                      |
| Cross-store `storeParams` link (T6b review)                 | Would suppress the `search` event; no such in-app link today. Add a pinning test.                                                                                                                                                                                                                                                                                                                                    |
| Slider load promise (T6c review)                            | Created inline on every render of the search page; fine for one server render, worth hoisting.                                                                                                                                                                                                                                                                                                                       |
| Rating clamp (T6c review)                                   | The slider star rating is capped at 5 (`Math.min`); no test covers a rating above 5.                                                                                                                                                                                                                                                                                                                                 |
| Stale `.next/dev/types/validator.ts`                        | During T6a an old dev-server type file broke `typecheck` and `build`; not reproduced since T6b (checks pass with `.next/dev` in place). If it returns, stop the dev server and delete `.next/dev`.                                                                                                                                                                                                                   |
| Header autocomplete, last store, SKU jump                   | Not replicated (decision 9 and T4).                                                                                                                                                                                                                                                                                                                                                                                  |
| No cache                                                    | Every search runs CHAPI (1 call, or 4 for ChupaChoice); a single-store page adds `sort_by` (when the response has no sorts, always on staging today) and three Magento `randomProducts` calls.                                                                                                                                                                                                                       |
